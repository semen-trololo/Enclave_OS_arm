# Частые паттерны и ошибки

## Паттерн: MMIO без volatile
Неправильно: `*(uint32_t*)0x20201000 = value;`
Правильно: `*(volatile unsigned int*)(MMIO_BASE + 0x201000) = value;`
Почему: `-O2` убирает «лишние» чтения и записи, драйвер молча не трогает железо.

## Паттерн: запись в UART без ожидания TXFF
Неправильно: `UART_DR = byte;`
Правильно: `while ((UART_FR & TXFF) && timeout) timeout--; if (timeout) UART_DR = byte;`
Почему: байт теряется — FIFO PL011 переполняется на 115200. **Обязателен таймаут!**

## Паттерн: невыровненный стек
Неправильно: `ldr sp, =0x0001d65c`
Правильно: `ldr sp, =__svc_stack_top` (символ кратен 8)
Почему: AAPCS требует 8-байтного выравнивания SP, иначе кадр съезжает и дамп регистров врёт.

## Паттерн: возврат из исключения через bx lr
Неправильно: `bx lr`
Правильно: `subs pc, lr, #N`, для Data Abort — `#8`, для остальных — `#4`
Почему: при prefetch-исключении LR = PC+8; `subs` заодно восстанавливает CPSR из SPSR.

## Паттерн: implicit declaration
Неправильно: вызвать `uart_puts` из kernel_main.c без прототипа
Правильно: прототип в uart.h, `#include "uart.h"` в вызывающем файле
Почему: GCC 14 считает implicit declaration ошибкой, сборка падает.

## Паттерн: не-ASCII в строках, идущих в UART
Неправильно: `"готово ✓"`
Правильно: `"done"`
Почему: кодирование последовательного терминала неизвестно, строка превращается в мусор.

## Паттерн: GPPUDCLK в uart_init() вызывает зависание [13.11.2026]
Неправильно: `GPPUDCLK0 = (1<<14) | (1<<15); delay(150);`
Правильно: не использовать GPPUDCLK для GPIO14/15 на Pi 1 B+
Почему: на BCM2835 прошивка уже настроила подтяжки, попытка изменить их через GPPUDCLK виснет в цикле.

## Паттерн: LED active-low vs active-high [13.11.2026]
Неправильно: `GPSET1 = 1<<15; delay(); GPCLR1 = 1<<15;` — предполагать что GPSET = горит
Правильно: **читать datasheet** — ACT-LED (GPIO16) активен низким, GPIO47 активен высоким
Почему: GPSET устанавливает бит в 1 (высокий), GPCLR — в 0 (низкий). Если LED активен низким — он горит при GPCLR, гаснет при GPSET.

## Паттерн: init_uart_clock обязателен для корректного делителя [13.11.2026]
Неправильно: IBRD=1, FBRD=40 без `init_uart_clock` в config.txt
Правильно: `init_uart_clock=3000000` и `core_freq=250` в config.txt
Почему: делители вычисляются от реального такта UART. Без явного задания прошивка даёт 16MHz → baud rate ~5200 вместо 115200.
