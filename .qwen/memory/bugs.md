# Известные баги и решения

## 2026-11-12: boot.S перетирает boot_r0 в 0 [ИСПРАВЛЕН f194063]
- Причина: `mov r0, #0` до вызова kernel_main, хотя firmware уже передал r0=0
- Решение: убрать mov, пробросить r0 через firmware напрямую
- Фикс: f194063
- Файлы: boot.S

## 2026-11-12: probe_regs_preserved constraint "r" вместо "+&r" [ИСПРАВЛЕН f194063]
- Причина: GCC 14 мог размещать переменную в регистре, пересекающемся с метками
- Решение: "+r" → "+&r" (early-clobber)
- Фикс: f194063
- Файлы: kernel_main.c

## 2026-11-13: GPPUDCLK в uart_init() вызывал зависание [ИСПРАВЛЕН]
- Причина: запись в GPPUDCLK0 с циклом задержки 150 nop висла — GPIO подтяжки не инициализированы
- Решение: полностью удалить блок GPPUD/GPPUDCLK0 из uart_init()
- Файлы: uart.c (удалён блок)

## 2026-11-13: uart_putc() висел вечно без таймаута [ИСПРАВЛЕН]
- Причина: `while (UART_FR & (1u << 5));` — если UART не тактируется, цикл бесконечный
- Решение: добавить таймаут `0xFFFFFF` (≈100мс), если не успел — пропустить байт
- Файлы: uart.c, kernel_main.c

## 2026-11-13: LED active-low vs active-high confusion [ИСПРАВЛЕН]
- Причина: boot.S использует GPIO16 (активный низкий: GPCLR2 → горит), kernel_main — GPIO47 (активный высокий: GPSET1 → горит). Два разных пина, два разных поведения.
- Решение: boot.S LED убран, всё мигание перенесено в kernel_main.c на GPIO47
- Файлы: boot.S, kernel_main.c

## 2026-11-13: init_uart_clock=3000000 не применялся [ИСПРАВЛЕН]
- Причина: config.txt без `init_uart_clock` прошивка давала другой такт → делители IBRD=1/FBRD=40 не давали 115200
- Решение: добавить `init_uart_clock=3000000` и `core_freq=250` в config.txt
- Файлы: config.txt

## 2026-11-11: Ядро молчит, если вывод QEMU перенаправлен в pipe или файл
- Причина: `-serial stdio` при не-TTY stdout теряет вывод в буфере
- Решение: `-serial file:/tmp/ser.txt`, затем читать файл; либо `make run` в настоящем терминале
- Файлы: makefile (цель run)

## 2026-11-11: Ядро глушат два `-device loader` подряд
- Причина: loader с `addr=` перехватывает точку входа, второй loader перебивает загрузку ядра
- Решение: loader ровно один (инжекция ATAG на 0x100), ядро — через `-kernel`
- Файлы: — (команды прогона)

## 2026-11-11: `-kernel build/kernel.img` не запускается, ядро молчит
- Причина: сырой образ не ложится на 0x8000, по 0x8000 нули
- Решение: `-device loader,file=build/kernel.img,addr=0x8000,force-raw=on`
- Файлы: — (команды прогона)

## 2026-11-11: `*** пропущен разделитель`, make не запускается
- Причина: рецепты makefile набраны пробелами вместо табов
- Решение: табы в рецептах
- Файлы: makefile

## 2026-11-11: Номер ATAG читается не из того слова
- Причина: по самому 0x100 лежит `size` тега (для ATAG_CORE = 5), а номер тега — следующим словом, по 0x104
- Решение: читать и печатать оба слова, не подставлять номер по первому
- Файлы: kernel_main.c
