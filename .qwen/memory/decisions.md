# История решений

## 2026-11-11: Selftest живёт в основном образе ядра
- Причина: на плате нет ни монитора, ни gdb — вердикт PASS/FAIL ядро должно печатать само в UART
- Альтернативы: отдельная тестовая сборка (расходится с боевым образом), только ручной лог (перегон SD-карты ради одной строки)
- Файлы: kernel_main.c

## 2026-11-11: Три состояния проверки — PASS / FAIL / SKIP
- Причина: отсутствие ATAG-списка в QEMU есть свойство эмулятора, а не поломка ядра; FAIL врал бы о состоянии
- Альтернативы: валить вердикт в FAIL, молча пропускать без строки
- Файлы: kernel_main.c

## 2026-11-11: Границы обхода ATAG-списка: 2 слова на тег, 1024 слова, 64 тега
- Причина: мусор по 0x100 превращает ядро в висящую плату без единого символа в UART — чинить пришлось бы перегоняющей карту
- Альтернативы: обход без границ, только проверка магического числа ATAG_CORE по 0x100
- Файлы: kernel_main.c

## 2026-11-11: ELF затирает low memory в QEMU — лечится перед выходом на железо
- Причина: решение пользователя; лечение `-z max-page-size=0x1000` проверено, но правку сборки отложен
- Альтернативы: добавить опцию в LDFLAGS сразу
- Файлы: makefile

## 2026-11-12: Роли моделей — субагентами, а не командами
- Причина: загрузчик `.qwen/commands/*.md` читает только description / when_to_use / argument-hint, поле `model:` игнорируется; `model:` поддержан у субагентов, включая форму `openai:<id>`
- Альтернативы: команды с `model:` (всё пошло бы на главную модель, экономии нет), только субагенты без точек входа
- Файлы: .qwen/agents/, .qwen/commands/

## 2026-11-12: Нарушение делегирования — все задачи решены основной моделью
- Причина: код-ревью, исправления boot.S/kernel_main.c, обновление памяти — всё выполнено без делегирования `coder`/`debugger`. QWEN.md обязует делегировать; скиллы `code`/`debug`/`remember-bug` настроены, но не использованы.
- Альтернативы: делегировать через `tool_call(agent, subagent_type: "coder"/"debugger")` как определено в QWEN.md
- Файлы: QWEN.md, .qwen/agents/, .qwen/commands/
