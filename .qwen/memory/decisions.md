# Решения по кодеру

## 2026-11-13: Вердикт — ОСТАВИТЬ с жесткими правилами
- **Решение**: Оставить coder'а в проекте, но с жёсткими ограничениями
- **Причина**: Coder опасен при свободном использовании, но полезен для рутинных задач при строгом контроле. Увольнение и замена потребует времени на обучение нового субагента.
- **Альтернативы**: 🔴 Уволить — потребуется время на обучение; 🔒 Оставить без правил — риск потери архитектуры
- **Файлы**: `.qwen/agents/coder.md`, `.qwen/memory/delegate-to-coder.md`

## 2026-11-13: Стратегия работы с coder'ом
- Coder ДОЛЖЕН получать конкретные файлы, строки и содержимое в промте
- Максимум 30% изменений файла за одну задачу
- Автоматическая эскалация [ESCALATE] при сборке с ошибками или >30% изменений
- Максимум 1 coder параллельно — параллельные задачи вызывают хаос
- Обязательная проверка: `git diff` → `make clean && make` → QEMU тест
- Если не получилось 3 раза — [ESCALATE] на debugger
- Запрещено: boot.S, linker.ld, обработка исключений, архитектура
