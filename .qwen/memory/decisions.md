# История решений (обновлено 15.11.2026)

## 15.11.2026 — ревизия (код — коммит 767f0bf)
- IC: настоящий BCM2835 (pending RO / Enable WO / Disable WO), не PL190.
  Причина: записи PL190 уходили вне карты регистров; QWEN.md запрещает PL190.
- Тик: System Timer C1, не SP804. Причина: SP804 не реализован в QEMU; C0/C2 заняты GPU.
- soft-float до осознанного включения VFP. Причина: hard-float генерил VFP при выключенном cp10/11.
- QEMU — ELF, плата — raw img. Причина: QEMU грузит ELF по адресам сегментов (0x8000),
  raw — на 0x10000. Альтернатива: один -device loader,addr=0x8000,force-raw=on.
- sd/ — транзитный каталог, комплект пересобирается ВСЕГДА. Причина: залёжный config.txt
  уехал на карту и увёл baud. Доказательство: лог «config.txt, 972», «103448.300000 Hz».
- Выходные параметры функций — uint32_t* (arm-none-eabi: uint32_t=unsigned long).
- Неизвестные IRQ маскируются и считаются (spurious), не паникуют. Причина: ядро должно
  оставаться живым для UART-лога.
- Framebuffer принят в план как M4.5 (mailbox+fb-консоль), gpu_mem поднять 16→64 на этой вехе.
  Причина: нужен вывод на монитор; QEMU эмулирует mailbox+fb → проверяемо до платы.
- Логи платы коммитятся как доказательства (logs/board-*.log); новые логи — в .gitignore.
- Политика coder'а ОБНОВЛЕНА (заменяет запрет от 13.11): coder реализует все файлы плана,
  включая boot.S/linker.ld, с guardrails (≤30% файла, список НЕ ТРОГАТЬ, 3 попытки → ESCALATE).
  Основание: QWEN.md (зона человека) — приоритет над этой записью.
