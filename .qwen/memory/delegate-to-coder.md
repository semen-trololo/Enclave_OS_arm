# Как правильно делегировать задачи coder'у

**Дата:** 13.11.2026  
**Причина:** coder 4 раза за сессию не выполнил задачу, потому что промт был слишком общий

## ПРОБЛЕМА
Coder **не выполняет задачи**, если промт не содержит:
1. **Конкретных файлов и путей** (абсолютных, а не "обнови файл")
2. **Чёткого плана шагов** (шаг 1, шаг 2, шаг 3...)
3. **Обязательной проверки** (`make clean && make`, QEMU тест)
4. **Механизма эскалации** (что делать если что-то пошло не так)

## ЧТО НЕ РАБОТАЕТ
- ❌ "Исправь 3 бага в kernel_main.c" — слишком абстрактно
- ❌ "Создай interrupt.h, interrupt.c, добавь в makefile" — без конкретных путей и содержимого
- ❌ "Собери и протестируй" — без указания команд
- ❌ Нет таймаута — coder может зависнуть на бесконечном повторе

## ЧТО РАБОТАЕТ

### Полный шаблон промта для coder:

```
Ты — coder. Задача: [конкретное описание]. ВСЁ сделать полностью: [список действий].
НЕ ПЕРЕПИСЫВАЙ файлы целиком — только точечные правки. НЕ СКАЗЫВАЙ ЧТО НЕ МОЖЕШЬ — СДЕЛАЙ.

## ШАГ 1: Создать [файл]
Путь: /home/enclave/src/Enclave_OS_arm/[путь]
Содержимое: [полный код]

## ШАГ 2: Создать [файл]
Путь: /home/enclave/src/Enclave_OS_arm/[путь]
Содержимое: [полный код]

## ШАГ 3: Обновить [файл]
Путь: /home/enclave/src/Enclave_OS_arm/[путь]
Найти: [текст]
Заменить на: [текст]

## ШАГ N: Собрать проект
Выполнить: `make clean && make`
Результат: должен быть без ошибок

## ШАГ N+1: Протестировать в QEMU
Выполнить: `qemu-system-arm -M raspi1ap -kernel build/kernel.elf -display none -serial file:/tmp/qemu_serial.txt -no-reboot &`
Подождать 3 секунды.
Затем: `cat /tmp/qemu_serial.txt`
Должно быть: [ожидается]
Затем: `pkill qemu-system-arm`

## ШАГ N+2: Закоммитить
git add [файлы]
git commit -m "[сообщение]"

## ЖЁСТКИЕ ОГРАНИЧЕНИЯ:
1. НЕ ПЕРЕПИСЫВАЙ файлы целиком — только точечные правки
2. НЕ УДАЛЯЙ: [список функций]
3. После изменений — ОБЯЗАТЕЛЬНО `make clean && make` и тест в QEMU
4. Если файл не записался — попробуй ещё раз
5. НЕ ГОВОРИ "не могу", ДЕЛАЙ
```

## КЛЮЧЕВЫЕ ПРАВИЛА

1. **Путы к файлам — абсолютные** (`/home/enclave/src/Enclave_OS_arm/...`, а не "в корне проекта")
2. **Содержимое файлов — полностью** (не "добавь interrupt.h", а "создай interrupt.h с таким содержанием: ...")
3. **Команды сборки и теста — точные** (не "собери и протестируй", а "`make clean && make` и затем `qemu-system-arm ...`")
4. **Ожидаемый результат — явный** (не "проверь что работает", а "должно быть: `Enclave OS Booting...`")
5. **Запрет на "не могу" — прямой** (coder 4 раза говорил что не может писать файлы)
6. **Эскалация — если не удалось записать файл после 3 попыток**

## ЧТО ДЕЛАТЬ ЕСЛИ CODER ЗОВИС

Если coder не ответил за 5 минут или говорит что "не смог" — перехватываю задачу вручную.
Кодер не предназначен для сложных многошаговых задач — он делает только точечные правки.

## КОГДА ИСПОЛЬЗОВАТЬ CODER

- ✅ Точечные правки (1-2 строки)
- ✅ Добавление простого файла по шаблону (если промт очень подробный)
- ❌ Многошаговые задачи (3+ шага) — делать вручную
- ❌ Архитектурные изменения — делегировать debugger
- ❌ Анализ чужого кода — делегировать debugger
